広告制御機能

Unity LevelPlay による広告配信と、配信環境を App Store 配信版のみに限定する安全機構

v2.0 機能ID: RS-FEAT-AD

概要

本アプリはバナー広告とインタースティシャル広告、リワード広告を用いて無料ユーザー向けにマネタイズする。 広告ネットワークは Unity LevelPlay（Unity Ads をメディエーション経由の bidder として利用）。 プレミアム会員には広告を表示しない。

再発防止の設計（最重要）

AdMob 停止の原因は、開発中および TestFlight 検証中に本番の広告枠でインプレッションが発生していたことにある。 ネットワークを変えても自己インプレッションの禁止という規約は同じであるため、 広告のロード・表示を行うのは App Store 配信版のみとする構造をアプリ側に組み込んでいる。 この方針は LevelPlay への再移行後も一切変えていない。

項目内容
判定の中枢AdEnvironment.isAdDeliveryAvailable = !appKey.isEmpty && isProduction（App Key が設定済み かつ App Store 配信版）
配信可能な環境App Store 配信版のみ
配信しない環境DEBUG ビルド / シミュレーター / TestFlight（広告を一切リクエストしない）
判定方法App Store レシートの種別（sandboxReceipt かどうか）で判定する。ビルド構成の設定ミスでは破れない
SDK 初期化配信可能な環境でのみ実行する（不要な通信と起動コストを避ける）
ロード開始条件配信可能 かつ SDK 初期化完了後。LevelPlay は初期化前の loadAd() が失敗するため
ATT ダイアログ広告配信時のみ表示する（ATT 仕様書）
LevelPlay にも AdMob のような「テスト広告ID」の概念はない。 そのため開発中はテスト広告を出すのではなく、広告そのものを出さない方式を採用している。 レイアウト確認は広告枠のプレースホルダで行う。

処理フロー

sequenceDiagram participant App as RankingStadiumApp participant Env as AdEnvironment participant SDK as LevelPlay SDK participant V as View App->>Env: isAdDeliveryAvailable alt App Key 設定済み かつ App Store 配信版 Env-->>App: true App->>SDK: LevelPlay.initWith(LPMInitRequest) SDK-->>App: 初期化完了（AdReadiness.isInitialized = true） App->>V: 再描画（バナー表示条件の再評価） V->>SDK: 広告ロード要求 SDK-->>V: 広告 or 失敗（指数バックオフ・上限64秒で再試行） else それ以外（DEBUG / シミュレーター / TestFlight / App Key 未設定） Env-->>App: false Note over App,SDK: SDK 初期化も広告リクエストも一切行わない V-->>V: バナーは枠ごと非表示 / 報酬は広告なしで即付与 end

広告の種類と表示タイミング

LevelPlay の対応フォーマットはバナー・インタースティシャル・リワードの3種。表示面は移行前から変更していない。

種類フォーマット表示タイミング対象
バナーLPMBannerAdView（アダプティブバナー）MainTabView 共通配置（タブバー直上）無料ユーザーのみ
インタースティシャルLPMInterstitialAd起動時・フォアグラウンド復帰時・ログイン完了時無料ユーザーのみ
リワードLPMRewardedAd結果アンロック・ボーナスポイント受け取り（ユーザーの能動操作）全ユーザー（報酬目的）

表示頻度の制御（移行後も維持）

  • インタースティシャルは起動時・復帰時に最低10分間隔をあけて表示する
  • ログイン完了時のみクールダウンを無視して表示する
  • プレミアム会員にはインタースティシャル・バナーを表示しない
  • リワードによる報酬は1日5回まで（結果アンロック・ボーナスポイントそれぞれ）

広告配信が無効な期間の挙動（ユーザーから見た仕様）

App Key と広告ユニットID（バナー / インタースティシャル / リワードの3種）は設定済み。 ただし ironSource Ads アカウントが承認待ちのため、現時点で広告は配信されていない。 この状態でもアプリの機能は損なわれない設計とする。
広告広告が配信されない場合の挙動
バナー枠ごと非表示（空白を残さない）
インタースティシャル表示されない（呼び出し自体を行わない）
リワード報酬を広告なしで即付与する。1日の上限などの制御は維持する

該当する報酬導線

導線報酬上限文言
結果ロック画面結果アンロック ＋ 3pt1日5回「無料で結果を見る」
マイページ+3pt1日5回「ボーナスポイントを受け取る」

いずれも「広告を見て〜」という広告に言及する文言から、広告に言及しない表現へ変更済み。

課金訴求の変更

広告が配信されない状態で「広告非表示」を特典として掲げるのは実態と合わないため、 Paywall の特典一覧から該当項目を削除した。

項目状態
広告非表示削除
ランキング作成無制限維持
TOP3投票モード維持
長期間ランキング維持
選択肢30個まで維持
結果閲覧無料維持

広告を再開する際に元へ戻せるよう、コード上にコメントを残している。

ビジネスルール

  • 広告のロード・表示は App Store 配信版のみ。それ以外の環境ではリクエストを発生させない
  • SDK の初期化完了前は広告をロードしない（LevelPlay は初期化前の loadAd() が失敗するため）
  • プレミアム会員にはバナー・インタースティシャルを表示しない
  • 広告のロード・表示に失敗しても UX を止めない（バナーは非表示、全画面広告はサイレントでスキップ）
  • 広告が配信されない期間もリワードの報酬は付与し、機能を成立させる（上限制御は維持）
  • 広告に依存しないよう、報酬導線の文言は広告に言及しない

技術仕様

項目内容
SDKLevelPlay 9.6.0（SPM: LevelPlay-Swift-Package / プロダクト名 UnityMediationSDK）
アダプタLevelPlayUnityAdsAdapter 5.10.0（プロダクト名 UnityAdsAdapter）。SDK とは別のバージョン体系のため 9.x を指定すると依存解決に失敗する
導入方法Swift Package Manager（CocoaPods は使わない）。プロダクト名がパッケージ名と一致しない点に注意
ビルド設定OTHER_LDFLAGS に -ObjC が必須
初期化LPMInitRequestBuilder(appKey:) → LevelPlay.initWith(_:completion:)
初期化完了の伝播AdReadiness（@Observable / @MainActor）。素の static var だとバナーの表示条件が再評価されず、初期化前に描画された画面でバナーが出なくなる
バナーLPMBannerAdView + LPMAdSize.createAdaptive()。高さは適応型サイズをそのまま使い固定値でクリップしない。破棄時に destroy() が必須
全画面LPMInterstitialAd / LPMRewardedAd。showAd は viewController を必須で要求する
ロード状態LevelPlay の全画面広告には isLoading / isShowing が無いため、マネージャ側で状態を保持する
再試行ロード失敗時は指数バックオフ（上限64秒）で再試行。再試行タスクは1本に束ねて多重実行を防ぐ

エラー処理

発生条件対応
バナーのロード失敗枠ごと非表示（空白を残さない）
インタースティシャルのロード失敗サイレントでスキップ。指数バックオフで再ロード
リワードのロード失敗広告なしで報酬を付与（上限制御は維持）
SDK 初期化の失敗広告以外の機能は動き続ける。原因調査のため Logger には必ず記録する
App Key 未設定広告を一切ロードしない（安全側の既定）

実装メモ

  • LevelPlay 9.6.0 + UnityAds アダプタ 5.10.0 を SPM で導入。OTHER_LDFLAGS に -ObjC を追加
  • AdEnvironment.isAdDeliveryAvailable ですべての広告処理を分岐（バナー・全画面で非対称にしない）
  • App Store レシートの種別で本番配信版を判定（#if DEBUG 分岐のみに依存しない）
  • SDK 初期化も配信可能な環境でのみ実行
  • 初期化完了を @Observable な AdReadiness で SwiftUI に伝播（バナーの表示条件を再評価させる）
  • 全画面広告のロードは SDK 初期化完了後にのみ行う（初期化完了時にもロードを呼び直して取りこぼしを防ぐ）
  • アダプティブバナーの高さをそのまま使い、固定値でクリップしない。破棄時に destroy() を呼ぶ
  • 指数バックオフの再試行タスクを1本に束ね、多重実行を防止
  • 報酬コールバックの到達順に依存しない実装（報酬の取りこぼしを防止）
  • 広告未配信時のリワード報酬即時付与と、日次上限制御の維持
  • Paywall 特典から「広告非表示」を削除（再開時に戻せるようコメントを残す）
  • App Key・広告ユニットID3種を設定済み
  • ironSource Ads アカウントの承認完了を待つ（承認されるまで配信は始まらない）

広告制御機能

AppLovin MAX による広告配信と、配信環境を App Store 配信版のみに限定する安全機構

v1.0 機能ID: RS-FEAT-AD

概要

本アプリはバナー広告とインタースティシャル広告、リワード広告を用いて無料ユーザー向けにマネタイズする。 広告ネットワークは AppLovin MAX。プレミアム会員には広告を表示しない。

2026-07-30、AdMob アカウントが「無効なトラフィック」により恒久的に無効化された。 再審査請求も却下され、新規アカウントの作成を含めて AdSense / AdMob は今後一切利用できない。 このため広告基盤を AppLovin MAX へ全面移行した（2026-07-30 〜 2026-08-04）。

関連画面

  • ホーム（バナー・起動時インタースティシャル）
  • 結果ロック画面（結果アンロックの報酬導線）
  • マイページ（ボーナスポイント受け取り導線）
  • Paywall（プレミアム特典の訴求）

再発防止の設計（最重要）

AdMob 停止の原因は、開発中および TestFlight 検証中に本番の広告枠でインプレッションが発生していたことにある。 ネットワークを変えても自己インプレッションの禁止という規約は同じであるため、 広告のロード・表示を行うのは App Store 配信版のみとする構造をアプリ側に組み込んでいる。

項目内容
判定の中枢AdEnvironment.isAdDeliveryAvailable = 「SDK Key が設定済み」かつ「App Store 配信版である」
配信可能な環境App Store 配信版のみ
配信しない環境DEBUG ビルド / シミュレーター / TestFlight（広告を一切リクエストしない）
判定方法App Store レシートの種別（sandboxReceipt かどうか）で判定する。ビルド構成の設定ミスでは破れない
SDK 初期化配信可能な環境でのみ実行する（不要な通信と起動コストを避ける）
ATT ダイアログ広告配信時のみ表示する（ATT 仕様書）
AppLovin には AdMob のような「テスト広告ID」の概念がない。 そのため開発中はテスト広告を出すのではなく、広告そのものを出さない方式を採用した。 レイアウト確認は広告枠のプレースホルダで行う。

広告の種類と表示タイミング

種類フォーマット表示タイミング対象
バナーMAAdView（アダプティブバナー）MainTabView 共通配置（タブバー直上）無料ユーザーのみ
インタースティシャルMAInterstitialAd起動時・フォアグラウンド復帰時・ログイン完了時無料ユーザーのみ
リワードMARewardedAd結果アンロック・ボーナスポイント受け取り（ユーザーの能動操作）全ユーザー（報酬目的）

表示頻度の制御（移行後も維持）

  • インタースティシャルは起動時・復帰時に最低10分間隔をあけて表示する
  • ログイン完了時のみクールダウンを無視して表示する
  • プレミアム会員にはインタースティシャル・バナーを表示しない
  • リワードによる報酬は1日5回まで（結果アンロック・ボーナスポイントそれぞれ）

広告配信が無効な期間の挙動（ユーザーから見た仕様）

現在 AppLovin の publisher アカウントが審査中のため、SDK Key と広告ユニットIDは未設定（空）。 そのため現時点では広告は一切配信されていない。この状態でもアプリの機能は損なわれない設計とする。
広告広告が配信されない場合の挙動
バナー枠ごと非表示（空白を残さない）
インタースティシャル表示されない（呼び出し自体を行わない）
リワード報酬を広告なしで即付与する。1日の上限などの制御は維持する

該当する報酬導線

導線報酬上限文言
結果ロック画面結果アンロック ＋ 3pt1日5回「無料で結果を見る」
マイページ+3pt1日5回「ボーナスポイントを受け取る」

いずれも「広告を見て〜」という広告に言及する文言から、広告に言及しない表現へ変更済み。

課金訴求の変更

広告が配信されない状態で「広告非表示」を特典として掲げるのは実態と合わないため、 Paywall の特典一覧から該当項目を削除した。

項目状態
広告非表示削除
ランキング作成無制限維持
TOP3投票モード維持
長期間ランキング維持
選択肢30個まで維持
結果閲覧無料維持

広告を再開する際に元へ戻せるよう、コード上にコメントを残している。

ビジネスルール

  • 広告のロード・表示は App Store 配信版のみ。それ以外の環境ではリクエストを発生させない
  • プレミアム会員にはバナー・インタースティシャルを表示しない
  • 広告のロード・表示に失敗しても UX を止めない（バナーは非表示、全画面広告はサイレントでスキップ）
  • 広告が配信されない期間もリワードの報酬は付与し、機能を成立させる（上限制御は維持）
  • 広告に依存しないよう、報酬導線の文言は広告に言及しない

エラー処理

発生条件対応

実装メモ

  • AppLovinSDK 13.6.3 を SPM で導入。OTHER_LDFLAGS に -ObjC を追加
  • AdEnvironment.isAdDeliveryAvailable ですべての広告処理を分岐（バナー・全画面で非対称にしない）
  • App Store レシートの種別で本番配信版を判定（#if DEBUG 分岐のみに依存しない）
  • SDK 初期化も配信可能な環境でのみ実行
  • アダプティブバナーの高さをそのまま使い、固定値でクリップしない
  • 指数バックオフの再試行タスクを1本に束ね、多重実行を防止
  • 報酬コールバックの到達順に依存しない実装に変更（報酬の取りこぼしを防止）
  • 広告未配信時のリワード報酬即時付与と、日次上限制御の維持
  • Paywall 特典から「広告非表示」を削除（再開時に戻せるようコメントを残す）
  • AppLovin publisher アカウントの審査完了後に SDK Key と広告ユニットIDを設定する

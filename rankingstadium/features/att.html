ATT（App Tracking Transparency）

iOS 14.5+ 必須のトラッキング許可ダイアログ制御仕様

v1.1 機能ID: RS-FEAT-ATT

概要

Apple の App Tracking Transparency（ATT）フレームワークに基づき、広告ネットワークによる IDFA（広告識別子）利用前にユーザーの許可を求める。 許可状況に応じて AppLovin MAX がパーソナライズ広告と非パーソナライズ広告を切り替える。

2026-08-04 更新: 広告基盤を AdMob から AppLovin MAX へ全面移行した（AdMob が恒久的に利用不可になったため）。 あわせて、ATT ダイアログを表示するのは広告配信時のみに限定した。 AdEnvironment.isAdDeliveryAvailable が false の環境（DEBUG / シミュレーター / TestFlight / SDK Key 未設定）では、 広告をリクエストしないためトラッキング許可も求めない。詳細は 広告制御 を参照。

プロンプト表示タイミング

ContentView の authenticated 遷移（ホーム表示後）で ATTrackingManager.requestTrackingAuthorization を1回要求する。 ただし要求するのは広告配信が有効な環境のみ。
条件動作
AdEnvironment.isAdDeliveryAvailable が falseプロンプトを表示しない（広告をリクエストしないため）
アプリが active のときプロンプトを表示する
アプリが inactive のときプロンプトを表示しない（OSが無視するため）
scenePhase が .active に復帰したとき未許諾（.notDetermined）であれば再試行して取り逃しを防ぐ
すでに許可 / 拒否済み再プロンプトは表示しない（OS 制御）

処理フロー

sequenceDiagram participant App as ContentView participant Env as AdEnvironment participant ATT as ATTrackingManager participant MAX as AppLovin MAX App->>App: authenticated 遷移 (ホーム表示) App->>Env: isAdDeliveryAvailable alt 広告配信が無効（DEBUG / シミュレーター / TestFlight / SDK Key 未設定） Env-->>App: false Note over App,MAX: ATT プロンプトを表示しない else 広告配信が有効（App Store 配信版） Env-->>App: true App->>App: scenePhase == .active を確認 App->>ATT: requestTrackingAuthorization() ATT-->>App: status (.authorized / .denied / .restricted / .notDetermined) alt status == .authorized App->>MAX: IDFA 利用 (パーソナライズ広告) else status != .authorized App->>MAX: IDFA 非利用 (非パーソナライズ広告) end end Note over App: scenePhase 復帰時に .notDetermined なら再試行

NSUserTrackingUsageDescription

Info.plist に設定するユーザー向け説明文（App Store 審査で具体性を求められる）:
あなたの興味・関心に合った広告を表示するため、広告識別子（IDFA）の利用許可をお願いしています。許可しない場合も、アプリの全機能をご利用いただけます。

AppLovin MAX との連携

ATT ステータス広告配信の動作
.authorizedIDFA を利用したパーソナライズ広告を配信
.denied / .restrictedIDFA を利用しない非パーソナライズ広告を配信
.notDetermined非パーソナライズ広告（プロンプト未回答の間）
AppLovin MAX SDK は ATT の許可状況を OS から検出して IDFA 利用 / 非パーソナライズを切り替える。 アプリ側でフラグを手動設定する必要はない。

ビジネスルール

  • ATT プロンプトは広告配信が有効な環境でのみ表示する（App Store 配信版かつ SDK Key 設定済み）
  • ATT プロンプトはアプリ起動中に1度のみ表示（iOS OS 制御）
  • 許可・拒否にかかわらず、アプリの全機能を利用可能とする
  • 設定アプリから後から変更可能であることを設定画面で案内する
  • プロンプトは active 状態のときのみ要求し、inactive 時は要求しない

エラー処理

発生条件対応
requestTrackingAuthorization が inactive 状態で呼ばれたscenePhase == .active のガードで防止

実装メモ

  • ContentView の authenticated 分岐後に ATT 要求処理を実装
  • scenePhase 監視で復帰時の再試行を実装
  • NSUserTrackingUsageDescription を具体的な文言で Info.plist に設定
  • ATT 要求を AdEnvironment.isAdDeliveryAvailable でガードし、広告配信時のみ表示
  • AppLovin MAX SDK の ATT 自動切替を利用（アプリ側の手動フラグ設定は不要）

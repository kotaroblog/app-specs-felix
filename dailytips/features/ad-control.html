広告制御機能

AppLovin MAX 4種広告（Banner / Interstitial / Rewarded / AppOpen）の表示制御

v2.0 機能ID: DT-FEAT-AD

2026-08-04 広告基盤を AdMob から AppLovin MAX へ全面移行

AdMob アカウントが「無効なトラフィック」により恒久的に無効化され、再審査請求も却下された。 新規アカウント作成も含めて AdSense / AdMob は今後一切利用できないため、AppLovin MAX へ移行した。

AppLovin の publisher アカウントは審査中のため、SDK Key と広告ユニットIDは未設定。 現時点で広告は一切配信されていない（後述の安全機構により、未設定の間は自動的に無効）。

概要

本アプリは 4種類の AppLovin MAX 広告 を統合し、画面・タイミング別に最適な広告を出す。 プレミアム会員は全広告非表示。動画報酬やカレンダー解放で能動的な広告視聴も可能。

広告を出してよい環境の判定（再発防止の中枢）

AdMob 停止の原因は、開発中・TestFlight 検証中に本番の広告IDでインプレッションが発生していたことだった。 ネットワークを変えても同じ規約（自己クリック・他者への視聴依頼の禁止）が適用されるため、同じ事故を構造的に防ぐ。

AdEnvironment.isAdDeliveryAvailable = 「SDK Key が設定済み」かつ「App Store 配信版である」

環境広告のロード・表示
DEBUG ビルド一切リクエストしない
シミュレーター一切リクエストしない
TestFlight一切リクエストしない
App Store 配信版（SDK Key 設定済み）配信する
  • 判定は App Store レシートの種別（sandboxReceipt かどうか）で行う。ビルド構成の設定ミスでは破れない
  • AppLovin にはテスト広告IDの概念がないため、開発中は広告を出さない方式を採用した
  • SDK 初期化自体も配信可能な環境でのみ実行する（起動コストと不要な通信を避ける）
  • ATT（トラッキング許可）ダイアログも広告配信時のみ表示する。広告がないのに許可を求める状態を作らない

広告配信が無効な期間の挙動

種類挙動
Banner枠ごと非表示（空白を残さない）
Interstitial / AppOpen表示しない。広告リクエストも発生しない
Rewarded広告なしで報酬を即付与（1日の上限などの制御は維持）

該当する導線は「過去の豆知識の日付解放（ホーム・カレンダー・検索の3箇所）」と「ボーナスポイントの受け取り」。 文言も広告に言及しない表現（「無料で解放する」「ボーナスを受け取る」）へ変更済み。

また、広告が配信されない状態で「広告を完全に非表示」をプレミアム特典として掲げるのは実態と合わないため、 プレミアム紹介の特典一覧から該当項目を削除した（過去の豆知識をすべて閲覧・毎月100ptボーナス・ジャンル解放がお得は維持）。 広告を再開する際に戻せるよう、コード上にコメントを残している。

広告の種類と表示タイミング

種類Manager表示タイミング無料/プレミアム
Banner—（BannerAdView）HomeView 下部に常時無料のみ
InterstitialInterstitialAdManagerジャンルクイズプレイ開始時無料のみ
RewardedRewardedAdManager動画ボーナス・カレンダー解放（能動）常時利用可（報酬獲得）
AppOpenAppOpenAdManager起動時・フォアグラウンド復帰時無料のみ

広告ユニットID の構成

AdConfig に4種類の広告ユニットIDを集約する。AppLovin ダッシュボードで発行した値を設定し、 未設定（空）の間は広告を一切ロードしない（差し替え漏れで意図しない挙動にならないための安全弁）。

enum AdConfig {
    // AppLovin ダッシュボードで発行して設定する
    static let bannerID = ""
    static let interstitialID = ""
    static let rewardedID = ""
    static let appOpenID = ""
}

※ 実際のIDは本仕様書には記載しない（コード上で管理する）。

関連画面

  • ホーム画面（Banner / 動画ボーナス）
  • カレンダー（Rewarded解放）
  • ジャンルクイズプレイ（Interstitial）

各 Manager の責務

RewardedAdManager（@MainActor : NSObject）

  • show(onReward:onFailed:) で表示
  • 視聴完了時 onReward コールバック実行
  • 失敗時 onFailed コールバックでエラー通知
  • 動画ボーナス: CoinService.recordVideoBonus()
  • カレンダー解放: HistoryService.markAsAdViewed()

InterstitialAdManager

  • ジャンルクイズプレイ開始時に表示
  • 未ロード時はサイレントで次画面へ

AppOpenAdManager

  • loadAd() で事前ロード（SDK初期化完了後に実行）
  • show(isPremium:) でプレミアム判定込みで表示
  • scenePhase 変化監視でフォアグラウンド復帰時に自動再ロード
  • ATT許可後にロード再試行
  • 広告の有効期限を4時間で管理（期限切れは再ロード）

シート内からのリワード広告

  • topMostViewController() で最上位VCを取得して表示（シート内から呼び出し可能）

ビジネスルール

  • プレミアム会員は すべて非表示（Rewarded のみ報酬目的で利用可）
  • 広告ロード失敗時は UXを止めない（Banner: 高さ0、Interstitial: スキップ）
  • AppOpen は起動 UX を阻害しないため、ロード失敗時はサイレント
  • AppOpen は表示間隔4時間・1日3回上限。フォアグラウンド復帰のたびに全画面広告が出ると ユーザー体験を著しく損ない、パブリッシャー ポリシー違反にあたるため必ず絞る。 表示できない期間は広告リクエスト自体を行わない
  • Interstitial はクイズ回答3回に1回
  • 広告ロード失敗時は指数バックオフ（上限64秒）で再試行する

実装メモ

  • 各Manager は @MainActor : NSObject
  • DEBUG/Release で AdConfig がID切替（DEBUGはGoogle公式テストID使用）
  • scenePhase == .active で AppOpen 再表示判定・自動再ロード
  • AppOpen 広告: SDK初期化完了待ち → ATT許可後に再試行 → 4時間有効期限管理
  • DEBUGビルドでもテスト広告ID（AdConfig 経由）でアプリ起動広告を表示し動作確認可能（v1.0.7で改修）
  • topMostViewController() でシート内から Rewarded 広告表示可能
  • SKAdNetworkItems 71件を Info.plist に登録（AdMob 公式推奨リスト）

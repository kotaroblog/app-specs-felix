広告制御機能

Unity LevelPlay 3種広告（Banner / Interstitial / Rewarded）の表示制御 ／ アプリ起動広告は廃止

v3.0 機能ID: DT-FEAT-AD

2026-08-20 広告基盤を AppLovin MAX から Unity LevelPlay へ移行

AdMob アカウントが「無効なトラフィック」により恒久的に無効化（2026-07-30）され、再審査請求も却下された。 その後 AppLovin MAX へ移行したが、publisher アカウントの承認が下りなかったため断念し、Unity LevelPlay へ再移行した。

App Key と広告ユニットID（Banner / Interstitial / Rewarded）は設定済み。 ただし ironSource Ads アカウントが承認待ちのため、現時点で広告はまだ配信されていない。

広告基盤の変遷

時期基盤結果
〜2026-07-30Google AdMobアカウントが恒久的に無効化。AdSense / AdMob は今後一切利用できない
2026-07-30 〜 2026-08-20AppLovin MAX移行完了したが publisher アカウントの承認が下りず断念
2026-08-20 〜Unity LevelPlay移行完了。アプリ起動広告（App Open）は廃止。ironSource Ads アカウント承認待ち

Unity Ads は 2026-04-01 以降、直接統合だと配信性能が落ちるため、LevelPlay（メディエーション）経由の bidder として利用する。直接統合は使わない。

概要

本アプリは 3種類の Unity LevelPlay 広告（Banner / Interstitial / Rewarded）を統合し、画面・タイミング別に最適な広告を出す。 プレミアム会員は全広告非表示。動画報酬やカレンダー解放で能動的な広告視聴も可能。

アプリ起動広告（App Open）の廃止

LevelPlay にはアプリ起動広告（App Open）のフォーマットが存在しない。 対応フォーマットはバナー・インタースティシャル・リワードの3種のみで、SDK にも App Open 相当のクラスがない （AdMob の GADAppOpenAd、AppLovin の MAAppOpenAd にあたるものが提供されていない）。

つまり起動広告は「移行できない」のではなく「移行先が無い」状態にある。

項目内容
方針停止で確定（2026-08-20）。起動時の広告収益はゼロとして扱う
コードの扱いAppOpenAdManager は API を残した無効スタブ。loadAd() / showAdIfAvailable(isPremium:) は意図的な no-op（ログも出さない）
スタブにした理由呼び出し側（起動時・フォアグラウンド復帰時）を書き換えると将来の復活時に差分が広がるため
広告ユニットIDAdConfig.appOpenID は空文字のまま未使用
復活の条件App Open を持つ別ネットワーク（AdMob・AppLovin MAX 等）の併用が必要。いずれも現在使えないため比較対象が存在しない
収益の受け皿起動広告のぶんはインタースティシャル（クイズ回答3回に1回）が受け持つ

LevelPlay の承認が下りて実際に収益が立ってから、DailyTips だけ別ネットワークを併用するかを改めて判断する。

広告を出してよい環境の判定（再発防止の中枢）

AdMob 停止の原因は、開発中・TestFlight 検証中に本番の広告IDでインプレッションが発生していたことだった。 ネットワークを変えても同じ規約（自己クリック・他者への視聴依頼の禁止）が適用されるため、同じ事故を構造的に防ぐ。

AdEnvironment.isAdDeliveryAvailable = !appKey.isEmpty && isProduction （App Key が設定済み かつ App Store 配信版）

環境広告のロード・表示
DEBUG ビルド一切リクエストしない
シミュレーター一切リクエストしない
TestFlight一切リクエストしない
App Store 配信版（App Key 設定済み）配信する
  • 判定は App Store レシートの種別（sandboxReceipt かどうか）で行う。ビルド構成の設定ミスでは破れない
  • LevelPlay にもテスト広告IDの概念がないため、開発中は広告を出さない方式を採用している
  • SDK 初期化自体も配信可能な環境でのみ実行する（起動コストと不要な通信を避ける）
  • SDK の初期化完了前は広告をロードしない。LevelPlay は初期化前の loadAd() が失敗するため、初期化完了（AdReadiness）を待ってからロードする
  • ATT（トラッキング許可）ダイアログも広告配信時のみ表示する。広告がないのに許可を求める状態を作らない

広告配信が無効な期間の挙動

種類挙動
Banner枠ごと非表示（空白を残さない）
Interstitial表示しない。広告リクエストも発生しない
Rewarded広告なしで報酬を即付与（1日の上限などの制御は維持）

該当する導線は「過去の豆知識の日付解放（ホーム・カレンダー・検索の3箇所）」と「ボーナスポイントの受け取り」。 文言も広告に言及しない表現（「無料で解放する」「ボーナスを受け取る」）へ変更済み。

また、広告が配信されない状態で「広告を完全に非表示」をプレミアム特典として掲げるのは実態と合わないため、 プレミアム紹介の特典一覧から該当項目を削除した（過去の豆知識をすべて閲覧・毎月100ptボーナス・ジャンル解放がお得は維持）。 広告を再開する際に戻せるよう、コード上にコメントを残している。

広告ユニットID の構成

AdConfig に広告ユニットIDを集約する。Unity ダッシュボード（LevelPlay）で発行した値を設定し、 未設定（空）の間は広告を一切ロードしない（差し替え漏れで意図しない挙動にならないための安全弁）。

enum AdConfig {
    // Unity ダッシュボード（LevelPlay）で発行して設定する
    static let bannerID = "..."
    static let interstitialID = "..."
    static let rewardedID = "..."
    // アプリ起動広告は LevelPlay に該当フォーマットが存在しないため未使用
    static let appOpenID = ""
}

※ 実際のID・App Key は本仕様書には記載しない（コード上で管理する）。

関連画面

  • ホーム画面（Banner / 動画ボーナス）
  • カレンダー（Rewarded解放）
  • ジャンルクイズプレイ（Interstitial）

各 Manager の責務

RewardedAdManager（@MainActor : NSObject）

  • show(onReward:onFailed:) で表示（LevelPlay の showAd は viewController が必須）
  • 視聴完了時 onReward コールバック実行
  • 失敗時 onFailed コールバックでエラー通知
  • 動画ボーナス: CoinService.recordVideoBonus()
  • カレンダー解放: HistoryService.markAsAdViewed()
  • 広告配信が無効な期間は広告を呼ばずに報酬を即付与する

InterstitialAdManager

  • ジャンルクイズの回答3回に1回表示
  • 未ロード時はサイレントで次画面へ
  • LPMInterstitialAd には isLoading / isShowing が無いため、状態は Manager 側で保持する

AppOpenAdManager（無効スタブ）

  • 2026-08-20 に無効化。LevelPlay に App Open フォーマットが存在しないため
  • loadAd() / showAdIfAvailable(isPremium:) は API を維持したまま no-op
  • 呼び出し側（起動時・フォアグラウンド復帰時）のコードは変更していない
  • 旧仕様（4時間の有効期限管理・表示間隔4時間・1日3回上限・ATT 許可後の再試行）はすべて停止中

シート内からのリワード広告

  • topMostViewController() で最上位VCを取得して表示（シート内から呼び出し可能）

ビジネスルール

  • 広告のロード・表示は App Store 配信版のみ。DEBUG・シミュレーター・TestFlight では一切リクエストしない
  • SDK の初期化完了前は広告をロードしない
  • プレミアム会員は すべて非表示（Rewarded のみ報酬目的で利用可）
  • 広告ロード失敗時は UXを止めない（Banner: 枠ごと非表示、Interstitial: サイレントでスキップ）
  • Interstitial はクイズ回答3回に1回
  • アプリ起動広告は表示しない（フォーマット自体が存在しないため）
  • 広告ロード失敗時は指数バックオフ（上限64秒）で再試行する

エラー処理

広告種類失敗時の挙動
Banner枠ごと非表示（高さ0）
Interstitialサイレントでスキップ。指数バックオフで再ロード

実装メモ

  • 各Manager は @MainActor : NSObject
  • LevelPlay 9.6.0 + UnityAds アダプタ 5.10.0 を SPM で導入（プロダクト名はパッケージ名と一致しない）
  • AdEnvironment.isAdDeliveryAvailable で全広告処理を分岐
  • 初期化完了を @Observable な AdReadiness で SwiftUI に伝播し、バナー表示条件を再評価させる
  • 全画面広告のロードは SDK 初期化完了後にのみ行う
  • バナーは破棄時に destroy() を呼ぶ（LevelPlay はバナーの明示破棄が必要）
  • topMostViewController() でシート内から Rewarded 広告表示可能
  • AppOpenAdManager を API 維持のまま無効スタブ化（呼び出し側は無改修）
  • App Key・広告ユニットID3種を設定済み
  • ironSource Ads アカウントの承認完了を待つ（承認されるまで配信は始まらない）
  • 起動広告を復活させるかは、LevelPlay の収益実績を見てから判断する
